# Сборка и подготовка публикации Match Finder

## 1. Текущий порядок

Исходники хранятся в закрытом репозитории [yusha144/OldenEra-MatchFinder](https://github.com/yusha144/OldenEra-MatchFinder). Публичный доступ и выпуск на сайте модов пока не включены. Сохранение коммита на GitHub не публикует архив для игроков.

Проект собирается локально. CI/CD, GitHub Actions, Pages и Wiki для сборки не используются. DLL, ZIP, журналы, настройки игрока и сторонние библиотеки в Git не добавляются.

## 2. Требования

Нужны Git, PowerShell 7, .NET SDK 8 или новее, среда .NET 8 и собственная установленная игра с BepInEx Unity.IL2CPP 6.0.0-be.788. Библиотеки `BepInEx/core` и `BepInEx/interop` должны присутствовать. Путь к игре передаётся аргументом, личные пути в проект не записываются.

## 3. Подготовка коммита и архива

1. Внесите изменения, согласуйте версии в `source/MatchFinder.csproj`, `source/Plugin.cs` и инструкции. Обновите описание изменений и статус проверок.
2. Просмотрите `git diff` и `git status`, выполните автономные проверки. Сохраните необходимые файлы коммитом.
3. Выполните команду ниже из папки проекта, заменив пример на свою папку игры:

```powershell
.\Build-Release.ps1 -GameRoot 'C:\Games\OldenEra' -Revision HEAD
```

Скрипт извлекает выбранный коммит в отдельный каталог `work/release-*`, проверяет файлы игры, запускает проверки и собирает DLL в конфигурации Release. Рабочие изменения вне коммита в архив не входят. Сам скрипт должен соответствовать выбранному коммиту.

В `releases/` появятся:

- `OldenEra-MatchFinder-0.1.3.zip`, архив для установки.
- `OldenEra-MatchFinder-0.1.3.zip.sha256`, контрольная сумма архива.
- `OldenEra-MatchFinder-0.1.3.release.json`, локальная запись о версии, коммите и сумме.

Папку вывода можно изменить через `-OutputDirectory`. Существующие файлы скрипт не перезаписывает. При повторной проверке используйте новую папку. В ZIP находятся только DLL, инструкция игроку и `release-manifest.json` с контрольными суммами. Скрипт не устанавливает мод, не запускает игру, не создаёт тег и не выполняет загрузку в сеть.

## 4. Проверка перед распространением

Сверьте версию DLL, состав архива, коммит в описании сборки и SHA256. Проверьте отсутствие игровых библиотек, конфигураций и журналов. Выполните [ручные проверки](testing.md), особенно ещё не проверенные режимы. Лицензия авторского кода пока не выбрана; условия распространения нужно определить до публичного выпуска.

Любое исправление после сборки требует нового коммита и нового архива. Ранее опубликованные теги и архивы не заменяются: для исправлений используется новый номер версии.

## 5. Будущая публикация

Сайт модов и страница публикации ещё не выбраны. После отдельного решения о выпуске архив можно разместить там с описанием, требованиями, ограничениями, авторством и контрольной суммой. Открывать исходники на GitHub для распространения готового мода не требуется.

Если дополнительно понадобятся GitHub Releases, выпуск должен ссылаться на тот же коммит, из которого собран архив. После загрузки скачайте архив через GitHub заново и сравните SHA256. Пока репозиторий закрыт, такой выпуск доступен только пользователям с доступом к нему. Создание выпусков этим проектом автоматически не выполняется.
